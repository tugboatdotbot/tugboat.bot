The alternatives compared

For: the owner choosing a product, and the builder choosing what to build on. Last checked: November 10, 2026.

The short version

Section titled “The short version”
  • There are four kinds of product, plus Tugboat, the one we are building: open-source systems you run yourself, hosted personal assistants, hosted “AI employee” platforms, and features built into the AI apps.
  • What separates them is mechanism, not features. Where does the agent run, and where do your mail and messages live? What stays running when you are not there? Who is paid for the AI, and how? What stops the agent from acting without you?
  • For the systems you run yourself, we can answer those questions in detail, because their code and documentation are public. That comparison is the feature matrix. This page is the map around it.
  • For hosted products we mostly cannot. Their inner workings are not published. That is itself a fact to weigh.
  • Tugboat is not the right choice for most people today. A stranger cannot install it yet.

We make one of the things compared here. We ran none of the others. An agent on this page is one AI worker: a model that uses tools in a loop to get a job done. Other terms are in the glossary.

The systems you run yourself, in one paragraph each

Section titled “The systems you run yourself, in one paragraph each”

Each of these has a full column in the feature matrix. Facts are from each project’s documentation and code on November 10, 2026.

OpenClaw. One always-on program, the gateway, holds about 30 chat channels, every session and the scheduler. It has no AI in it; it passes work to agents. OpenClaw runs its own agent loop against dozens of model providers, or hands a turn to Claude Code or Codex. An agent is a folder of Markdown files plus a small database. By default the agent’s commands run on your machine with no sandbox and no approval step; both can be switched on, and an optional plugin can hold a send until you approve it. It is by far the most used, with about 394,000 GitHub stars, and has the largest security history.

Hermes Agent. Also a gateway with its own agent loop, written in Python by Nous Research. It runs natively on Windows. It keeps two deliberately small memory files and searches the full text of every past session. By default it writes and updates its own skills, which are reusable instruction files; that is what its makers mean by “self-improving”. Commands run on the host unless you choose a container. It supports more than 25 chat apps.

Paperclip. Not an assistant but a server for running a “company” of agents: an org chart, tasks with one assignee each, budgets, an audit log. It has no agent loop of its own. It starts other programs, such as Claude Code or Codex, for one short run at a time. Its server can hold an outgoing action until a person approves it. That is the most general gate of this kind we found, and it is off by default. Its chat connectors are experimental, and its Telegram and Slack connectors need a public web address.

NanoClaw. A small system built on Claude Code. Every conversation runs in its own container, a sealed box on your computer, and API keys are kept outside the box. You customise it by having Claude Code change NanoClaw’s own source code, so your installation becomes your own variant. On Windows it needs WSL2, a Linux layer inside Windows.

Claude Code on its own. Anthropic’s program, left running, with nothing third-party added. It has three official chat channels (Telegram, Discord, iMessage), all in research preview, and its own scheduled tasks. Nothing starts by itself when the computer does. Chat messages are delivered only while a session is open, and a timer set inside a session ends with it.

Tugboat. A gateway, with no AI in it, on one Windows PC. It starts Claude Code for one run per message, on the person’s own plan, with no window open. Since November 11 it runs one agent that reads mail, WhatsApp and Signal without changing anything, and puts a summary on a local web page. That agent has no tool that sends, reaches the internet or writes a file. Follow-through is being moved into the gateway; an older arrangement of several Telegram agents does it by instruction today. One user, no installer.

Which to choose, and the mechanism behind each choice

Section titled “Which to choose, and the mechanism behind each choice”

Each line gives the reason in terms of how the system works, and what that same design costs you.

You want no installation, and your mail living in someone’s cloud is acceptable. Choose a hosted product: Poke or Martin for yourself; Lindy, Sintra or Marblism for a small business. Why: the agent, its schedule and its connections all run on the maker’s servers, so there is nothing to keep alive. The cost: your mail and messages are stored there, and you cannot inspect how approvals or limits are enforced.

A morning brief or a scheduled prompt is all you need. Use what is built into Claude or ChatGPT. Why: it is included in a subscription, and the AI company runs it. The cost: it is a schedule plus a prompt. Nothing owns an open item or comes back to it.

You want one assistant in many chat apps, on the model of your choice, and you will run and secure it yourself. Choose OpenClaw or Hermes Agent. Why: each is a gateway with its own agent loop, so it can hold dozens of chat channels and speak to dozens of model providers, including models on your own machine. The cost: by default the agent’s commands run on your computer with no sandbox, add-on skills are other people’s code, and both projects release weekly with breaking changes. Between the two: Hermes Agent treats Windows as a first-class system and keeps memory small and searchable. OpenClaw has the larger community and more channels, and the longer security history.

You want Claude as the agent, with the strongest wall around it. Choose NanoClaw. Why: it runs Claude Code inside a container per conversation and keeps the keys outside. The cost: it needs Docker, and on Windows WSL2. Customising it means changing its source code.

You run many agents on queues of work and need budgets, an audit trail and approvals. Choose Paperclip. Why: a server with a database keeps every task, every run and every cost, gives each task exactly one assignee, and can hold an action for a person’s yes. The cost: it brings no agent of its own, its chat connectors are experimental, and it does not install on Windows without WSL2.

Nothing may slip, nothing may go out without your yes, and you already pay for Claude. This is what Tugboat is for. Why: the agent that reads your messages has no tool that sends, reaches the internet or writes a file, and the gateway enforces that in code. The list of open items, each with a date, is kept by the gateway, and the gateway does the asking, so it does not depend on the AI. The cost today: a stranger cannot install it, it does not send by itself yet (you press Send in Gmail), it runs only on Windows, and nobody but its builder has used it.

What people complain about

Section titled “What people complain about”

These are anecdotes from review sites and forums, searched on November 10, 2026. Several sources are competitors of the product they review. Treat them as hints, not measurements.

  • Hosted “AI employee” platforms. Reviews say their output is generic unless it is heavily set up. Sintra has a recent cluster of one-star reviews about its move to metered pricing. Lindy scores 1.5 of 5 on Trustpilot across 37 reviews, mostly about credits and cancelling, against 4.9 of 5 on G2.
  • OpenClaw. Adoption is very large. There are also many accounts of people stopping in the first week: setup that costs more than it returns, memory that breaks without warning, instability.
  • Hermes Agent. Reviews mention high token use per turn, and a memory limit that is smaller than it sounds.
  • Paperclip. Reviews say you run the whole stack yourself and that cost is hard to forecast.
  • The AI apps’ own features. This is our reading, not a gathered complaint: they give a schedule plus a prompt, and nothing owns an item or chases it.
  • Tugboat. It works for the person who built it and tends it daily. Nobody else has run it yet, so the same complaints about setup and upkeep could fairly be made of it.

What we make

Tugboat is our attempt at the combination that is hard to find: follow-through as a system, records you can read on your own computer, and nothing sent in your name without your tap on the exact text. It runs for its builder and is not yet installable by anyone else. Where Tugboat stands.
