How the main agent systems are built: a feature matrix

For: the builder, and the decider in a team. Last checked: November 10, 2026; Tugboat's column on November 11, 2026.

The short version

Section titled “The short version”
  • There are two families. OpenClaw and Hermes Agent run their own agent loop against model APIs. Paperclip, NanoClaw and Tugboat run no loop of their own. They drive a harness that someone else makes, most often Claude Code.
  • Four of the five outside systems run the agent’s commands on your own machine with no sandbox, unless you turn one on. NanoClaw is the exception: every session runs in a container.
  • Almost nothing stops an agent from sending by default. Three systems can hold an outgoing action in code until a person says yes: Paperclip, OpenClaw through an optional plugin, and NanoClaw for requests that use a chosen secret. None of the three is switched on by default.
  • None of the five keeps asking a person who has not answered. They time out, carry on with their best guess, or park the task. Tugboat’s older arrangement does keep asking, by written instructions. The gateway’s version, where code does the asking, is being built.
  • The gap in scale is enormous. OpenClaw has about 394,000 GitHub stars and Hermes Agent about 262,000. Tugboat has one user and cannot yet be installed by a stranger.

How to read this page

Section titled “How to read this page”
  • Rows are mechanisms, not marketing features. Each cell says what the system does and how: a file name, a default, a protocol.
  • Click any cell for a fuller account, the kind of evidence behind it, and links to the sources.
  • “Not found” means we could not find out in the sources we read. It does not mean the system lacks the thing. Where a system does lack it, the cell says “None”.
  • “Docs say” marks a claim by the project that nobody tested for this page. We ran none of these systems for this comparison, except our own.
  • Tugboat has two entries per row: what runs today, and what is being built. A plan is never written as if it existed.
  • Every fact has a date. These projects release weekly. The version examined is in the first table.

Terms such as gateway, harness and channel are explained in the glossary.

What stands out

Section titled “What stands out”

These are the differences that decide which system fits. Each one points at rows in the tables below.

1. Who runs the agent loop

Section titled “1. Who runs the agent loop”

The agent loop is the cycle of “read, act, check, repeat” that turns a model into an agent. The program that runs it is the harness.

  • OpenClaw and Hermes Agent are harnesses. Each has its own loop and talks to model providers directly. That is why they can use almost any model, including local ones.
  • Paperclip has no loop. It is a server that starts other harnesses (Claude Code, Codex, Cursor and others) for one short run at a time, and keeps the queue, the records and the budget.
  • NanoClaw and Tugboat use Claude Code as the harness. NanoClaw starts it through Anthropic’s Agent SDK inside a container. Tugboat’s gateway starts the Claude Code a person signed in to, for one run per message, with no window.
  • OpenClaw can also hand a turn to Claude Code or Codex in place of its own loop. Hermes Agent has two opt-in routes of the same kind, one in beta and one experimental.

What follows from this: a system with its own loop controls memory, context and tools in detail, and must keep up with every model itself. A system that drives Claude Code inherits Anthropic’s work, and Anthropic’s rules.

2. What stays running

Section titled “2. What stays running”
  • A gateway in OpenClaw and Hermes Agent: one always-on process that owns the chat connections, the sessions and the scheduler. An operating-system service restarts it, if you install one.
  • A server with a database in Paperclip: Node.js with Postgres.
  • A host process plus containers in NanoClaw: one container per active conversation.
  • Nothing starts at boot in Claude Code on its own. A session is a process, in a terminal or under a background supervisor that Claude Code starts when first needed. A background session survives a closed terminal and sleep, but not a shutdown. Its docs say chat messages arrive only while a session is open. Telegram keeps unread messages for a while, so a short gap is probably recovered; we did not test that.
  • Tugboat now has a small gateway, kept running by a supervisor and set to start when the person signs in to Windows. The older arrangement beside it is four sessions in terminal tabs with a nightly restart.

3. Using a Claude subscription

Section titled “3. Using a Claude subscription”

All five outside systems accept an API key. They differ on a monthly Claude plan, and this is where the vendors’ rules bite.

  • OpenClaw runs the Claude Code you installed and signed in to, and keeps it running across turns. Its docs call this sanctioned.
  • Hermes Agent has its own sign-in that presents itself as Claude Code. Its docs say this needs a Max plan with paid extra usage, and that Pro does not work.
  • Paperclip and NanoClaw use a long-lived token that Claude Code issues (claude setup-token). NanoClaw’s setup lists the subscription first and its walkthrough uses it. Its docs say nothing about Anthropic’s terms.
  • Tugboat’s gateway starts the unmodified Claude Code that the person installed and signed in to, on their own plan. For anyone but its builder, that is the unclear case on our rules page. It can also use an API key, untried with a real key.

Whether each of these is allowed is not the same question as whether it works. See what Anthropic and OpenAI allow.

4. Where commands run

Section titled “4. Where commands run”

OpenClaw, Hermes Agent, Paperclip and Claude Code all run the agent’s shell commands on the host, as you, unless you choose a sandbox. Claude Code has no command sandbox on native Windows at all. Paperclip also switches off the harness’s own permission prompts, because nobody is there to answer them.

NanoClaw takes the opposite position. It switches the prompts off too, and makes a container the boundary for every session, with API keys held outside it.

Tugboat’s agent that reads private messages has no shell, file or web tool at all. The gateway starts each run with only the tools on its allowlist. That is a narrow allowlist, not a sandbox. The older arrangement runs commands on the host with no sandbox and relies on Claude Code’s permission rules and auto mode.

5. A person’s yes before sending or spending

Section titled “5. A person’s yes before sending or spending”

This is the row where the systems are weakest.

  • Paperclip has the most general gate. An action that goes through its tool gateway can be held; the run ends; a person approves; the server then performs the stored action itself. It is switched off by default for almost every app, and it does not cover the harness’s own tools.
  • NanoClaw can hold any request that uses a chosen secret until an admin approves it.
  • OpenClaw has an optional plugin, Lobster, that stops a workflow before it sends, posts or deletes, and resumes once someone approves. It is not installed by default and covers only actions run through such a workflow.
  • Hermes Agent and Claude Code have approvals for dangerous commands or tool calls. We found none aimed at outgoing messages.
  • Tugboat cannot send at all today: the agent has no tool that sends. A “propose, approve, send” step, where the gateway holds the permission and sends the exact approved text once, is being built.

6. A scheduled run that was missed

Section titled “6. A scheduled run that was missed”

A laptop that was asleep at 8:00 is the ordinary case at home, so this matters more than it looks.

  • Hermes Agent: runs a missed job once when it comes back. That is the default.
  • OpenClaw: reschedules overdue jobs and can catch up missed ones at a controlled pace.
  • Paperclip: runs a missed job once when the server comes back and skips the rest. Its docs say missed runs are dropped; its code fires one. Back-filling up to 25 is an option.
  • Claude Code: timers inside a session are never caught up. The desktop app runs one catch-up.
  • Tugboat: the gateway runs a missed task once when it is running again, and records every skipped run with its reason. This passes its tests and has not yet been seen after a real power-off.

7. Chasing the person

Section titled “7. Chasing the person”

Every system can ask a question. None of the five keeps asking. Hermes Agent denies an approval after five minutes. OpenClaw waits fifteen minutes and then continues on its own judgment. Paperclip chases agents that stall, not people who go quiet.

This is the one thing Tugboat is built around: each open task has one owner, a date and a time to ask again, and an unanswered question is asked again. Be clear about where that stands, though. In the older arrangement that runs today, a script marks a question as due for re-asking and the agent asks because its instructions say to. In the gateway, where code does the asking, it is being built.

8. Memory

Section titled “8. Memory”

Four of the five keep memory in plain Markdown files that the agent writes. Paperclip has none in its core. Among the four, the differences are in size and upkeep.

  • Hermes Agent caps its two memory files at 2,200 and 1,375 characters, and makes up for it with full-text search over every past session.
  • OpenClaw keeps a curated file plus daily notes, and promotes items overnight.
  • Both write their own skills by default. That is what “self-improving” means in practice.
  • Paperclip leaves memory to the harness, an optional notes skill and experimental memory connectors.
  • Tugboat’s agent keeps no notes file. It reads a searchable local store of the person’s messages and mail through the gateway. The older agents keep one notes file each.

9. Channels, and whether your home needs a public address

Section titled “9. Channels, and whether your home needs a public address”

A channel that polls, or holds an outgoing connection, works from a home computer with nothing exposed. A channel that needs a webhook requires a public web address or a tunnel.

  • Telegram polls in OpenClaw, Hermes Agent, NanoClaw and Claude Code. In Paperclip it is webhook-only.
  • Microsoft Teams needs a public endpoint in both OpenClaw and Hermes Agent.
  • WhatsApp in OpenClaw is an unofficial linked-device session. Hermes Agent offers the same, and its docs warn of a small risk to the account. It also offers Meta’s official API, which needs a public web address.
  • Claude Code has three official channels, all in research preview. Tugboat’s older arrangement uses one of them, Telegram. Its gateway serves its own web page, and has its own Telegram connection, built and switched off.

10. Windows

Section titled “10. Windows”

Hermes Agent and Claude Code run natively on Windows as a first-class target. OpenClaw runs natively and rates that support Alpha. Paperclip’s installer refuses native Windows, though agents it manages have been able to run there since July 2026. NanoClaw needs WSL2, a Linux layer inside Windows. Tugboat is Windows-first, and untested elsewhere.

11. The security record

Section titled “11. The security record”

Every system with a public record has a long one. Claude Code lists 36 advisories. Paperclip lists twelve, several critical. NanoClaw published nine in one day. OpenClaw’s own advisory list is by far the longest, at about 720 entries; it also had a one-click remote code execution flaw and 341 malicious skills in its registry. Hermes Agent’s own advisory page is empty while an outside tracker lists 45. Treat a long list as a sign of scrutiny as much as of weakness, and an empty one with care.

12. Where Tugboat is behind, and where it differs

Section titled “12. Where Tugboat is behind, and where it differs”

Read down the last column and the picture is plain. Tugboat is behind on almost every row: one channel in use, no installer, no sandbox, one user, and the list and the asking not yet in code.

What it does that the others do not:

  • Follow-through as a data model. One owner, a date and a time to ask again on every task, and questions that are asked again. In the gateway this is being built; the older arrangement does it by instruction.
  • The agent that reads cannot act. It has no tool that sends, reaches the internet or writes a file, and the gateway enforces that. Sending, once built, belongs to the gateway, never to the agent.
  • It uses the first-party harness unmodified. The gateway starts Anthropic’s own Claude Code on the person’s own subscription. OpenClaw and Paperclip can start it too, so this is a difference of emphasis, not a unique feature.
  • Everything is a readable file. The code is in version control; the record is a plain text file on the PC.

Whether that is enough to build on, or better offered as an addition to one of the larger systems, is an open question for us.

Section titled “Limits of this comparison”
  • A second model checked the findings above. It tested 65 claims in the short version and “What stands out” against the live sources on November 10, 2026. Three were wrong and nine overstated; all twelve are corrected here. The long tables were not checked cell by cell.
  • We read; we did not run. Apart from Tugboat, every cell comes from documentation, source code, release notes or reporting. A default described in the docs may differ from what an installer sets.
  • The pages were read through a tool that summarises. Short quotes are as it returned them. Check the source before relying on exact wording.
  • Docs disagree with themselves. Several projects have pages that contradict each other after a fast release. Where we saw it, the cell says so.
  • Security counts are not comparable. A project that publishes every advisory looks worse than one that publishes none.
  • Stars measure attention, not quality or safety.
  • It ages fast. At least three of these systems changed their core architecture between August and November 2026.
